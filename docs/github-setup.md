# GitHub Submission Setup

Repository name: `fitflow-redesign`

## Publish

1. Create a new GitHub repository named `fitflow-redesign`.
2. Keep it private unless the lecturer requires public visibility.
3. Upload the contents of this prepared repository or push the existing local Git history.
4. Confirm the default branch is `main`.
5. Copy the final URL and paste it into Section 6.1 of the Lab 05 report.

## Recommended repository settings

- Require a pull request before merging to `main`.
- Require at least one approval when a team workflow is used.
- Require the `documentation-check` / CI status check.
- Block force pushes and branch deletion for normal contributors.
- Never commit `.env`, passwords, private keys, database credentials or Auth0 secrets.
- Enable dependency alerts once implementation dependencies are actively maintained.

## Existing local commit

The repository has a real local Git history. The initial documentation/architecture commit is preserved in the local working copy. After publishing, subsequent commits may include the starter scaffolds prepared for the three application areas.
